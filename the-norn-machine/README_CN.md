## 1. 摘要

当前基于大语言模型（LLM）的生成式应用，常面临幻觉不可控、长上下文导致延迟飙升等挑战。主流解决方案往往试图通过检索增强生成（RAG）或复杂的 Prompt 工程来缓解，但并未从根本上改变“LLM 同时承担决策与表达双重职责”的结构性问题。

The Norn Machine 提出了一条不同的路径：**让确定性规则处理决策逻辑，让 LLM 专注于语言渲染。**

我们去除了初期计划的大量人工预设文本，引入了结合“选择轮次衰减”、“犹豫时长”与“反悔次数”的权重算法。配合 CloudFront + API Gateway 的基础云防御架构，在最终生成环节仅将浓缩的“行为画像骨架”交给 LLM 进行实时渲染。系统采用无状态（Stateless）设计，不存储受访者数据，在保障隐私的同时尝试追求更低的响应延迟。

## 2. 设计哲学：三个核心探讨

本架构尝试回应当前 AI 落地过程中的几个常见工程误区。

### 2.1 拒绝黑盒：谨慎让大模型做逻辑推演

**常见误区**：将用户行为或大量上下文直接交给 LLM，让模型自行推演用户的心理特征或下一步动作。这容易导致同样的输入在不同时间产生不一致的输出，增加幻觉风险。

**架构思路**：大模型本质上是概率文本生成器，而非精确的计算引擎。在 The Norn Machine 中，我们在“快思考引擎（Fast Thinker）”里，用确定性的算法来处理逻辑。通过引入 **“越晚选择权重越高（轮次衰减）”**、**“犹豫时间加权（Hesitation Tracking）”** 以及 **“选择后取消的判定”**，我们将这些隐性行为在代码层收敛为具体的特征座标。大模型在这个系统中只作为“渲染器”，负责将结构化数据转化为自然语言。

### 2.2 控制上下文：用状态压缩缓解记忆膨胀

**常见误区**：为了维持“人设”或对话连贯性，大量依赖极长的上下文窗口，将长篇的对话历史全部塞入 Prompt。这不仅增加了 API 成本和响应延迟，也容易引发大模型对中间信息的遗忘（Lost in the Middle）。

**架构思路**：我们尝试**极简的状态压缩与无状态（Stateless）设计**。系统不保留用户的长篇“对话原文”，仅在代码层动态更新用户的“行为倾向座标”。每次请求对于后端都是独立的，只需将当下高度浓缩的几百字骨架传给 LLM。这种架构有效降低了单次请求的 Payload 大小，优化了响应时间，并且实现了零落盘——不依赖数据库存储用户会话。

### 2.3 动态渲染：基于行为骨架的实时生成

**常见误区**：传统的测试产品往往依赖事先写好的固定文案进行条件匹配，不仅需要极大的人工撰写和维护成本，且输出结果容易千人一面。

**架构思路**：用**实时渲染（Dynamic Rendering）**替代静态文案库。后端的有限状态机（FSM）向模型传递精确但干瘪的“行为画像骨架”（如决策偏好、盲区、压力反应等）。LLM 结合动态路由的 Few-Shot 示例（如直觉流或分析师风格），在运行时为该骨架补充细节。

更关键的是，**输入信息量直接决定了输出分辨率与对话深度**。如果受访者给出的选择少（轮次少），系统会加载更短、更模糊、更偏直觉流的模板，并严格限制后续的追问轮数；如果选择信息丰富，模板就会更为详尽、精准，系统也会相应开放更深度的对话轮次。即便最终的人格类型相同，也会因为犹豫时间或信息量的不同，由 LLM 渲染出截然不同的行文侧重点。

## 3. 系统架构

### 3.1 全球加速与云防御拓扑

架构采用 Serverless 云原生形态：

```text
[用户 Browser] 
      │ (HTTPS)
      ▼
[AWS CloudFront CDN]  (内容分发、基础防 DDoS)
      │
      ▼
[AWS API Gateway]     (API Key 校验、请求限流)
      │
      ▼
[AWS Lambda]          (快思考算法 + Prompt 重排与组装)
      │
      ▼
[Amazon Bedrock]      (Claude 模型推理与 Guardrails)
```

- **CloudFront 分发**：前端静态资源通过边缘节点就近下发，优化大图加载延迟，并提供基础的 DDoS 防护。
- **API 限流**：API Gateway 配置了 Usage Plan 和 API Key，控制调用频率，防止恶意并发消耗大模型配额。

### 3.2 极简三步流水线

后端的 Lambda 承担核心调度，分为三步：

**Step 1：快思考引擎 (Fast Thinker)**
处理前端传入的 `[卡牌ID, 轮次, 犹豫时长, 取消次数]`。通过时间衰减和加权计算，快速得出受访者的特征座标。

**Step 2：模板路由与动态重排 (Template Router)**
系统根据算出的特征强度进行**动态重排（Reordering）**。将权重最高的隐性特质优先放置在 Prompt 顶部，利用 LLM 对前置信息的注意力优势，提升重点特征的表达优先级。

**Step 3：慢思考渲染 (Slow Thinker via Bedrock)**
向 Bedrock 注入重排后的 Prompt。LLM 将结构化的推演结果转化为连贯的反馈文本。

## 4. 安全与边界控制

对于公网 AI 应用，防止 Prompt Injection 与违规内容输出是重要考量。

### 4.1 对话环节的边界控制
在后续引入的对话交互中，架构设置了严格的约束：
- **基于信息量的动态轮数限制**：追问的深度严格与前端获得的信息量（选择轮次）绑定。不提供无限制的开放聊天，强制控制会话周期。
- **字数阻断**：在前端和后端均限制用户输入的字符数，降低长文本越狱攻击的风险。

### 4.2 Guardrails 护栏策略
利用 Amazon Bedrock Guardrails 增加安全过滤：
- 拒绝与判定无关的越狱指令。
- 过滤不当言论及敏感话题。
- 当触发拦截时，系统将平滑回退到预设的兜底话术（如：“命运之线缠绕过紧，织机暂无法解读”），保证体验的一致性。

## 5. 跨领域迁移能力

The Norn Machine 所采用的 **“隐性行为追踪 + 状态压缩 + 动态语言渲染”** 范式，具备向其他业务场景迁移的潜力：

### 5.1 对话式商品推荐（Conversational Commerce）

传统的电商筛选依赖静态标签，而当前的 AI 导购若强依赖 RAG，易受检索质量影响并可能推荐无库存商品。
本架构可提供一种替代思路：
- **行为追踪**：前端记录用户在浏览商品图片时的**犹豫时长**、**放大细节的操作**或**反复取消**的行为。后端将这些隐性数据量化为消费偏好骨架（例如：更关注视觉设计而非参数，或对某价格区间极度敏感）。
- **确定性库存白名单**：在代码层与真实的库存数据库核对，确保仅传递有货的商品 ID 列表。
- **动态渲染推销策略**：LLM 接收“消费骨架”与“确定的库存商品”。它不再负责检索商品，而是**专门负责运用最契合该用户偏好（如感性叙事或硬核数据解析）的话术，去介绍这件确定的商品**，从而可能提升转化率并避免商品幻觉。

### 5.2 智能客服与辅助系统

- **状态管理**：由后端逻辑维护标准业务流程（SOP）、用户当前的业务节点与合规边界。
- **行为压缩**：用户在查阅文档时的停留时间、在某些选项上的犹豫、或反复提问的行为被提取为状态参数。
- **对话渲染**：LLM 仅根据“当前业务骨架”与有限事实生成解答，既能以拟人化的口吻灵活应对边缘问题，又最大程度规避了不受限 Agent 设计带来的幻觉与胡言乱语风险。

### 5.3 个人 AI 智能名片

- **兴趣判断**：根据访客在数字简历不同版块的停留时间，推断其更关注技术深度还是商业经验。
- **事实渲染**：LLM 依据确定的个人履历事实，以访客最容易接受的侧重点和语调进行动态介绍。

## 7. 结论

The Norn Machine 的架构迭代试图说明：**在 AI 产品的工程实践中，为大模型设定清晰的边界同样重要。**

我们通过无状态设计减少了隐私负担，通过量化行为时间（犹豫、取消、衰减）辅助了意图捕捉；用 CDN 与限流保护了系统可用性；用动态重排和 Guardrails 限制了输出风险。最终，我们将语言渲染的灵活性留给了 LLM。

这不仅是一个性格测试的底层架构，也是在性能、安全、隐私与业务确定性之间寻找平衡的一次工程实践。
